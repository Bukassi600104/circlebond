## Data and rollout boundary

New checkout locks, device registrations, privacy requests and rate buckets are additive. All privileged connector operations are NO_ACCESS for direct client SDK callers and require authenticated server boundaries. The former direct user-profile mutation UpsertCurrentUser is now NO_ACCESS to prevent forged contact/consent writes; repository search found no shipped application caller. Its generated declaration does not grant execution rights. Actual public-client denial E2E remains required. No legacy records were rewritten or deleted.

The deadline job now uses a narrowly parameterized server-only SQL UUID cursor because generated UUID filters lack comparison operators. No dynamic SQL, DDL or destructive operation is used. Returned Any rows are checked. A independently closed offset-skip concurrency with three regressions; actual local SQL execution remains H's gate. Scheduler/provider load and operational alert routing require staging evidence.

Before any deployment: approved compatible schema rollout, backup, staging authorization/storage/concurrency verification and rollback rehearsal. Source/compiler/unit success does not replace these operations. The configured production bucket currently returns404 and legal pages retain owner-required placeholders. Connected Vercel credentials cannot access the owning project scope, so current live commit/rollback relation is unverified.
