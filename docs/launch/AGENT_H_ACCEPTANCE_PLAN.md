## Exact candidate gate

Run from an isolated tracked-clean candidate with the exact intended commit recorded. Preserve package/lock integrity and distinguish a reused dependency tree from a completed `npm ci`. Required commands remain `npm ci`, `npm run format:check`, `npm run lint`, `npm run typecheck`, `npm test` and `npm run build`. Do not launch competing builds/emulators while the parent integrates source changes.

The circle-engine runner includes only its Data Connect suites: `circle-engine.test.mjs`, `account-privacy.test.mjs`, `rate-limit.test.mjs`, `dashboard.test.mjs`, `retention-pagination.test.mjs` and `invitation-allocation.test.mjs`. Authentication retains its separate Auth/Data Connect wrapper. Synthetic operations must target explicit loopback emulators. Actual Storage writes additionally require an explicit local Storage emulator; never let an emulator test fall back to a production bucket.

## Browser and performance execution

- `scripts/qa-public-browser.mjs` runs the bounded public-page checks against an already running loopback candidate. Set `BONDCIRCLE_QA_URL` and `BONDCIRCLE_PLAYWRIGHT_PATH` to the existing Playwright entry point. Set `BONDCIRCLE_BROWSER_EXECUTABLE` to an existing compatible desktop browser when Playwright's bundled executable is unavailable. It records the commit, tracked cleanliness, browser version, exact lab profile, screenshots and individual assertions in ignored `tmp/launch-evidence/public-browser/`. Its mocked delivery checks cover browser recovery/routing only; real SMTP/Auth coverage remains separate. It does not start a server or download dependencies.
- Use the existing installed full Chromium through bundled Playwright; do not claim a simulated viewport is a physical device. Capture the browser version, candidate URL/commit, viewport and test assumptions.
- Test 390px phone, 768px tablet, 1280px desktop and landscape layouts; public/protected navigation, validation, keyboard focus, dialogs and interruption/error states. Use only synthetic local identities for authenticated journeys.
- Define lab budgets before measuring: public sign-in/onboarding LCP ≤2.5s and CLS ≤0.1; controlled interaction latency ≤200ms; warm local API p95 ≤800ms; valid local image-upload operation ≤5s excluding deliberate network transfer time. Record failures and host/network limitations; do not loosen budgets after seeing results.
- For a controlled slow-network sample, use 150ms added latency, 1.6Mbps download, 750kbps upload and 4× CPU slowdown, recording at least three fresh contexts. Report individual lab results and their small sample size. Single/local lab samples do not establish field p75 or real-device compliance.
- [Core Web Vitals guidance](https://web.dev/articles/vitals) defines field targets at p75: LCP2.5s, INP200ms and CLS0.1. Field/physical acceptance remains separate.
- Obtain real-device installation, standalone launch, safe areas, session/auth restoration, invitation navigation, sharing, uploads, app switching, offline and update sign-off. Missing hardware/provider access is BLOCKED, never PASS.

No production deployment, charge, live customer operation, destructive production purge, backup restore or public pilot invitation is authorized by this checklist alone.
